# Settings implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a settings page for appearance, editable keybindings, local account details, signatures, and the recipient recommendations extracted from mail or added manually.

**Architecture:** Keep theme and shortcut preferences on the current device. Store account names, signatures, and contact recommendations in each account's existing SQLite database. Extend the existing authenticated API, TanStack Hotkeys provider, composer, and app layout.

**Tech Stack:** TypeScript, React, TanStack Router, TanStack Query, TanStack Hotkeys, Bun, SQLite, Drizzle, Zod, Tailwind CSS, Playwright, and Vite+.

**Spec:** [Settings design](../specs/2026-11-07-settings-design.md).

## Global constraints

- Account edits and contact edits stay inside Mailfast. Google supplies account identity and mail access.
- Browser-local storage holds device preferences: theme and custom shortcuts.
- Per-account SQLite stores hold account names, signatures, and recommendations.
- Keep Dark as the default for existing installations so the change preserves their current appearance.
- A recording captures one chord. Escape cancels recording.
- Removing an extracted recommendation hides it so background sync cannot recreate it immediately.
- Preserve manually edited names when later mail syncs extract a different name.
- Changing a saved signature does not rewrite open drafts, and sending does not append it again.
- A failed save leaves the form available with its unsaved values and an actionable error.
- Reuse installed dependencies. Apps use `@/` imports. Generate Drizzle migrations through the existing CLI.
- Preserve the uncommitted mail import/export work present when this plan was written. Stage only task-owned changes when making commits.
- Execute inline unless the user selects subagents. Do not start a new worktree or delegate without the required authorization.

## Task 1: Durable contact recommendations and account settings

**Files:** Modify `packages/shared/src/index.ts`, `packages/db/src/schema.ts`, `packages/db/src/index.ts`, and `packages/db/src/store.test.ts`. Generate a new migration under `packages/db/migrations` and its metadata.

**Interfaces produced:**

```ts
type AccountSettings = { displayName: string; signature: string };
type ManagedContact = { email: string; name: string; hidden: boolean };
type ContactPage = { contacts: ManagedContact[]; nextOffset: number | null };
type SaveContact = { email: string; name: string; originalEmail?: string };

// Methods on MailStore. Types live in @mailfast/shared.
accountSettings(): AccountSettings;
saveAccountSettings(value: AccountSettings): void;
listContacts(opts: { q: string; hidden: boolean; offset: number; limit: number }): ContactPage;
saveContact(value: SaveContact): ManagedContact;
setContactHidden(email: string, hidden: boolean): void;
importContacts(values: Contact[]): number;
```

- [ ] Add shared Zod schemas. Account display names are trimmed and limited to 100 characters. Plain-text signatures allow newlines and are limited to 10,000 characters. Contact names are trimmed and limited to 200 characters. Emails are trimmed, lowercased, validated, and limited to 254 characters. Page offsets are nonnegative integers and page limits are between 1 and 100. Contact import batches contain at most 100 contacts.
- [ ] Add failing database tests using the existing in-memory store fixture:

```ts
store.recordContact("ALICE@example.com", "Extracted");
store.saveContact({ email: "alice@example.com", name: "My Alice" });
store.recordContact("alice@example.com", "Later extraction");
expect(store.searchContacts("alice")).toEqual([{ email: "alice@example.com", name: "My Alice" }]);
store.setContactHidden("alice@example.com", true);
store.recordContact("alice@example.com", "Another extraction");
expect(store.searchContacts("alice")).toEqual([]);
store.setContactHidden("alice@example.com", false);
expect(store.searchContacts("alice")[0]?.name).toBe("My Alice");
```

- [ ] Run `vp run @mailfast/db#test`. Expect failures for the missing management methods.
- [ ] Add nullable `manualName` and boolean `hidden` columns to `contacts`. Run `vp run @mailfast/db#generate` and inspect the generated SQL and journal. Preserve existing contact rows and counts. Keep automatic upserts from changing either new column.
- [ ] Resolve suggestion names with `COALESCE(manual_name, name)` and exclude hidden rows. Use the same effective name for management searches. Preserve prefix relevance and frequency ordering in composer search. Management pages use deterministic email ordering and fetch `limit + 1` rows to calculate `nextOffset`.
- [ ] Save account settings as one validated JSON value in the account store's `kv`, under `account_settings`. Return empty values when no record exists. Reject invalid stored values without preventing account startup.
- [ ] Implement contact writes in transactions. Email edits hide the original and upsert the replacement. Manual additions clear the replacement's hidden flag. Imports fill missing manual details but never overwrite manual names or restore hidden addresses. Repeating an import leaves the same recommendations.
- [ ] Add tests for empty manual names, normalized duplicates, replacing an email with an existing email, pagination, repeat imports, migration from the previous database, and two independent account stores. Run the database tests and `vp run @mailfast/db#check`. Commit only these changes.
